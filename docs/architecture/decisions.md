# Foundation architecture decisions

These decisions implement the approved architecture; they do not replace it. M0 proofs demonstrate compatibility within stated fixtures. Product integration, capacity and release/security gates remain on the roadmap.

| Decision              | Choice and rationale                                                                                             | Evidence / consequences                                                                                                                                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Product boundary      | Django owns product policy, metadata and migrations. Keep Node narrow and deny direct learner schema changes.    | PostgreSQL proof role has no metadata/DDL rights. Fixture SQL is not a production migration. Django/DRF/Channels pins are selected with M1 source, not installed without a use.                                                |
| Collaboration runtime | Node 24.22.3, Hocuspocus server/provider 4.8.0, Yjs 13.6.33; y-protocols 1.0.7 and lib0 0.2.117                  | Real-provider sync/checkpoint/reconnect/fault cases pass. Shared sockets need explicit provider attachment. v4 server-internal broadcast opcodes are rejected. Admission fixture is not production identity/lease enforcement. |
| Durable checkpoints   | pg 8.23.1 and PostgreSQL 18.7; binary merge, one shared per-document queue, SQL revision CAS and atomic receipts | Real transaction barriers, failure injection, SIGKILL collaboration restart and PostgreSQL immediate-shutdown recovery. No journal or immutable source history is implied by a receipt.                                        |
| Editor binding        | CodeMirror state 6.7.6/view 6.43.15 and y-codemirror.next 0.3.6                                                  | Browser binding proof applies edits both ways with Yjs text as owner. Full browser-to-server IDE, undo/cursor UI and access policy ship later.                                                                                 |
| Source identity       | Execution contract v1 hashes exact captured UTF-8 source and canonical sorted manifest                           | Immutable capture before async hashing; server/supervisor revalidation; generation/metadata/runtime/input-mode binding. No DOM-derived source or mutable manifest pointers.                                                    |
| Browser runtime       | Pyodide 314.0.7 core, self-hosted pinned assets, no arbitrary wheels                                             | Hash inventory checked before the test server listens. Python 3.14 verified in browsers. Backend Python 3.13 is a separate trusted runtime; native grading compatibility is explicitly not assumed.                            |
| Runner authority      | Different runner site, origin/source checked one-port handshake, dedicated supervisor and fresh Worker           | Real cross-site HTTPS headers, embedded isolation capability, no credential/parent-port bridge, Worker CSP and fixed static assets. Deployment must reproduce this topology.                                                   |
| Input and Stop        | SAB/Atomics only when embedded capability is present; declared batch fallback; hard Worker termination           | Interactive/EOF/cancel/infinite-loop/output-limit tests. Copy shared mailbox bytes before TextDecoder for Chromium. Soft interrupts and memory quotas are not required or promised by this proof.                              |
| Design                | Original semantic light/dark workbench tokens and explicit learning/save/run language                            | DESIGN.md and contrast checks. Components, Storybook, rendered design QA and product UX remain M1 onward. No reference code/assets copied.                                                                                     |
| Browser eligibility   | Chromium and WebKit are measured M0 targets on macOS arm64. Firefox is unverified due local launcher failure.    | Keep an explicit Firefox suite; do not silently skip it or claim Safari/Chrome/Firefox product certification from engine fixtures.                                                                                             |

Dependency locks and runtime asset hashes are the authoritative exact pins. Frameworks not exercised by M0 (React/Router/Query, Django/DRF/Channels, Redis/Celery) and deployment images are pinned and verified when introduced in M1. This avoids a speculative lock/image list that has never been started. Do not infer whole-stack compatibility from the proof dependencies.

The proof HTTP server and fixture admission are deliberately local and non-deployable. Its test TLS key/certificate are generated in an owned temporary directory and removed on shutdown; no trust-store changes. Runner build output alone does not contain a deployable runtime distribution: the fixture serves validated assets from the locked package. Production packaging/CSP, independent domains, secrets and auth must pass M1/M2 acceptance checks before any deployment request.
